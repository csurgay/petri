0 · Definíció és tüzelési szabály

Alapok: a háló, és mikor tüzel egy tranzíció?

Petri-hálóN = (P, T, F, w, M₀),   F ⊆ (P×T) ∪ (T×P),   w : F → ℕ⁺,   M₀ : P → ℕ

A kezdő jelölés a háló része. Ugyanaz a rajz más M₀-ból teljesen más állapotteret ad. Az 1-safe fejezet két hálója ugyanaz a (P, T, F, w) struktúra: 1 tokennel 1-safe, 2 tokennel nem. Ha ugyanezt a kört M₀ = (0, 0, 0)-ból indítjuk, azonnal holtpontban van. Ezért az oldal hat tulajdonsága viselkedési tulajdonság: mindig a teljes (P, T, F, w, M₀) hálóra vonatkozik.

Strukturális tulajdonságok. Ha M₀-t elhagyjuk, a (P, T, F, w) struktúráról is mondhatunk állításokat, ha M₀-ra kvantálunk. Például strukturálisan korlátos: ∀M₀ : P → ℕ esetén (P, T, F, w, M₀) korlátos. Strukturálisan élő: ∃M₀ : P → ℕ, amelyre (P, T, F, w, M₀) élő. A kvantor itt is számít: korlátosnak minden kezdő jelölésre kell lennie, élőnek elég egyre.

Tüzelési szabály

Minden tulajdonság erre épül. Egy tranzíció akkor engedélyezett, ha minden olyan helyen, ahonnan nyíl megy bele, legalább annyi token van, amekkora a nyíl súlya. Tüzeléskor elveszi ezeket a tokeneket, és a kimenő nyilai mentén újakat tesz le.

Engedélyezettségt ∈ E(M)  ⟺  ∀p ∈ P :  (p,t) ∈ F ⇒ M(p) ≥ w(p,t)
  1. t ∈ E(M) ⟺„t eleme az M-ben engedélyezett tranzíciók halmazának pontosan akkor, ha…
  2. ∀p ∈ P : (p,t) ∈ F ⇒…minden olyan p helyre, amelyből nyíl megy t-be, igaz, hogy…
  3. M(p) ≥ w(p,t)…azon a helyen legalább annyi token van, amennyit a nyíl elvisz."
Tüzelés: ha t ∈ E(M), az új jelölés M′∀p ∈ P :  M′(p) = M(p) − w(p,t) + w(t,p)

Ahol nincs nyíl, ott w = 0, tehát a hely tokenszáma nem változik.

Elérhető jelölések, lépésenként felépítve(1)  M₀ ∈ R(M₀)
(2)  ∀M ∈ R(M₀)  ∀t ∈ E(M) :  M′ ∈ R(M₀),  ahol M′ a t tüzelésének eredménye

  2. ∀M ∈ R(M₀) ∀t ∈ E(M)Ha egy jelölés elérhető, és benne t engedélyezett,…
  3. M′ ∈ R(M₀)…akkor a tüzelés utáni jelölés is elérhető." Más elérhető jelölés nincs.

Tüzelési sorozat: OS(M)

Maximális tüzelési sorozat (occurrence sequence) M-bőlOS(M) = M  t₁  M₁  t₂  M₂  …,   ahol ∀i : ti+1 ∈ E(Mi) és Mi+1 a ti+1 tüzelésének eredménye

A sorozat maximális: vagy végtelen, vagy olyan Mn jelölésben ér véget, ahol E(Mn) = ∅, tehát nem lehet tovább folytatni. Egy M-ből általában sok ilyen sorozat indul (minden választásnál elágazik). A ∀OS(M) „bármelyik ilyen sorozatra", a ∃OS(M) „van ilyen sorozat" jelentésű.

  1. |OS(M)|a sorozat hossza: hány tranzíció tüzel benne. Végtelen sorozatnál ∞, ami egyetlen b ∈ ℕ-nél sem ≤.
  2. M′ ∈ OS(M)M′ előfordul a sorozat jelölései között.
  3. t ∈ OS(M)t valahol tüzel a sorozatban.

Miért kell a maximalitás? Ha bármilyen (bővíthető) sorozatot megengednénk, az üres sorozat is OS(M₀) lenne, 0 hosszal. Ekkor a Deadlock formulája (lent) minden hálóra igaz, a Deadlock-free formulája minden hálóra hamis lenne. A Terminating, Reversible és Live formulákra a maximalitás nem hat, mert egy véges sorozat mindig kiegészíthető maximálissá.

1 · 1-safe

Biztonságos (1-safe)

Bármeddig futtatjuk a hálót, a hálóban összesen mindig pontosan egy token van. Ilyenkor a háló úgy viselkedik, mint egy állapotgép: a token helye mutatja, melyik állapotban van a rendszer.

Az oldalon ezt használjuk∀M ∈ R(M₀) :  Σp∈P M(p) = 1
  1. ∀M ∈ R(M₀)„Vegyük bármelyik jelölést, amely a kezdő jelölésből elérhető…
  2. Σp∈P M(p)…és adjuk össze az összes hely tokenszámát…
  3. = 1…az összeg pontosan 1."
A szakirodalomban gyakori, helyenkénti definíció∀M ∈ R(M₀)  ∀p ∈ P :  M(p) ≤ 1

A kettő nem ugyanaz. A helyenkénti változat csak azt kéri, hogy egyik helyen se legyen 1-nél több token. Az összeges változatból ez következik: ha az összeg 1, egyik tag sem lehet 1-nél nagyobb. Fordítva nem igaz: két token két különböző helyen, vagy egyetlen token sem, helyenként ≤ 1, de az összeg nem 1. Az összeges definíció tehát erősebb. Lásd a bizonyításokat.

2 · Bounded

Korlátos (bounded)

Létezik egy rögzített szám, k, amelynél több token soha nincs a hálóban összesen. A gyakorlatban: a pufferek véges méretűek, a rendszer nem „fut túl".

Az oldalon ezt használjuk∃k ∈ ℕ  ∀M ∈ R(M₀) :  Σp∈P M(p) ≤ k
  1. ∃k ∈ ℕ„Van egy természetes szám, k, úgy, hogy…
  2. ∀M ∈ R(M₀)…bármelyik elérhető jelölést nézzük…
  3. Σp∈P M(p) ≤ k…abban összesen legfeljebb k token van."
A szakirodalomban gyakori, helyenkénti definíció∃k ∈ ℕ  ∀M ∈ R(M₀)  ∀p ∈ P :  M(p) ≤ k

Itt a kettő ekvivalens, mert P véges. Ha az összeg legfeljebb k, akkor minden tag is legfeljebb k. Ha minden helyen legfeljebb k token van, akkor az összeg legfeljebb k·|P| (|P| a helyek száma). A korlát értéke más lehet, de korlát mindkét értelemben pontosan egyszerre van.

A sorrend a lényeg. A k-t előre kell kiválasztani, egyetlen közös korlátként, és utána kell működnie minden jelölésre. Ha fordítva írnánk, ∀M ∈ R(M₀) ∃k ∈ ℕ : Σp∈P M(p) ≤ k, az mindig igaz volna: minden egyes jelölésben véges sok token van, tehát mindegyikhez találunk saját k-t. A korlátlan változatban épp ez történik: minden lépésben van korlát, de az egyre nő.

tétel

korlátos ⟺ R(M₀) véges (véges állapottér)

Bizonyítás. (⇒) Legyen m = |P|. Ha minden elérhető jelölésben Σp∈P M(p) ≤ b, akkor R(M₀) elemei azon jelölések közül kerülnek ki, amelyek legfeljebb b tokent osztanak szét m helyre. Pontosan j tokent C(j+m−1, m−1)-féleképpen lehet szétosztani (golyók és válaszfalak: j golyó és m−1 válaszfal sorrendje). Legfeljebb b tokent C(b+m, m)-féleképpen (egy plusz „maradék" hellyel). Ez véges szám, tehát R(M₀) véges. (⇐) Ha R(M₀) véges, legyen b = maxM∈R(M₀) Σp∈P M(p). Ez jó korlát. ∎

Példa: m = 4 hely, b = 6 token, pontosan 6 token esetén C(9, 3) = 84 jelölés lehetséges.

3 · Terminating

Termináló (terminating)

Akárhogy választjuk a tüzelő tranzíciókat, a háló véges sok lépés után megáll. Nincs végtelen futás.

Definíció∃b ∈ ℕ  ∀OS(M₀) :  |OS(M₀)| ≤ b
  1. ∃b ∈ ℕ„Van egy b szám, hogy…
  2. ∀OS(M₀)…bármelyik M₀-ból induló maximális tüzelési sorozatot nézzük,…
  3. |OS(M₀)| ≤ b…az legfeljebb b lépés hosszú."

Egy végtelen sorozat hossza ∞, ez egyetlen b-nél sem ≤, így a formula a végtelen futásokat is kizárja.

Kifejtve E-vel: nincs végtelen futás¬ ∃t₁, t₂, … ∈ T  ∃M₁, M₂, …  ∀i ∈ ℕ :
 ti+1 ∈ E(Mi)  ∧  ∀p ∈ P : Mi+1(p) = Mi(p) − w(p,ti+1) + w(ti+1,p)
  1. ¬ ∃t₁, t₂, … ∈ T„Nem létezik olyan végtelen tranzíció-sorozat…
  2. ∃M₁, M₂, ……és hozzá olyan végtelen jelöléssorozat (M₀-ból indulva)…
  3. ∀i ∈ ℕ…hogy minden i-edik lépésre igaz:
  4. ti+1 ∈ E(Mi)a soron következő tranzíció engedélyezett az aktuális jelölésben,…
  5. ∀p ∈ P : Mi+1(p) = ……és a következő jelölés pontosan a tüzelés eredménye."

Miért ugyanaz a kettő? A definíció azt mondja, hogy a futások hossza korlátos, a kifejtett alak azt, hogy nincs végtelen futás. A futásokat egy fába rendezhetjük: gyökér M₀, minden jelölés gyerekei a belőle egy tüzeléssel elérhetők. Mivel T véges, minden csúcsnak véges sok gyereke van. A König-lemma szerint ha nincs végtelen ág, akkor a fa véges, tehát az ágak hossza korlátos.

4 · Deadlock

Holtpont (deadlock) és holtpontmentesség

Holtpont az az elérhető jelölés, ahol egyetlen tranzíció sem engedélyezett: a rendszer megakadt. A klasszikus példa: két folyamat két erőforrást fordított sorrendben foglal le, és mindkettő a másik által fogott erőforrásra vár.

M holtpont-jelölés∀t ∈ T :  t ∉ E(M)  (röviden: E(M) = ∅)
A hálóban van holtpont∃b ∈ ℕ  ∃OS(M₀) :  |OS(M₀)| ≤ b
  1. ∃b ∈ ℕ„Van egy b szám…
  2. ∃OS(M₀)…és van egy M₀-ból induló maximális tüzelési sorozat,…
  3. |OS(M₀)| ≤ b…amely legfeljebb b hosszú", vagyis véges.

Egy véges maximális sorozat azért ér véget, mert az utolsó jelölésében E(M) = ∅. Ez a jelölés a holtpont. A b itt el is hagyható (elég: van véges maximális sorozat), de vele jól látszik a párhuzam: a Terminating ∃b ∀OS, a Deadlock ∃b ∃OS.

5 · Reversible

Reverzibilis (reversible)

Bármilyen állapotba is jutott a háló, onnan mindig van út vissza a kezdő jelölésbe. A gyakorlatban: a rendszer bármikor „alaphelyzetbe" tud állni, pl. egy protokoll minden üzenetváltás után visszaér a nyugalmi állapotába.

6 · Live

Bizonyítások: implikációk és ellenpéldák

Az A ⇒ B állítás bizonyításához megmutatjuk, hogy minden hálóban, amelyben A teljesül, B is teljesül. Ahhoz, hogy az implikáció nem igaz, elég egyetlen háló (ellenpélda), amelyben A teljesül, B nem. Minden ellenpélda hálója itt helyben is fut. A helyeket a jelölésvektorban p₁, p₂, … sorrendben írjuk.

Minden ellenpélda mellett megadjuk a minimálisat is: azt, amelyben a helyek és tranzíciók együttes száma, |P| + |T|, a lehető legkisebb. Feltesszük, hogy P ∪ T ≠ ∅, különben nincs háló. Az ábrákon a „Minimális” gombbal lehet átváltani rá.

1. 1-safe és bounded

igaz

1-safe ⇒ bounded

Bizonyítás. Tegyük fel, hogy ∀M ∈ R(M₀) : Σp∈P M(p) = 1. Válasszuk a k = 1 értéket. Ekkor minden M ∈ R(M₀)-ra Σp∈P M(p) = 1 ≤ k. Tehát ∃k ∈ ℕ ∀M ∈ R(M₀) : Σp∈P M(p) ≤ k. ∎

nem igaz

bounded ⇒ 1-safe

Ellenpélda: a 2 tokenes kör (Bounded, „Korlátos"), M₀ = (1, 0, 1). Minden tranzíciónak egy bemeneti és egy kimeneti helye van, mindkét nyíl súlya 1. Így minden tüzelés 1 tokent vesz el és 1-et tesz le, tehát ∀M ∈ R(M₀) : Σp∈P M(p) = 2. A háló korlátos (k = 2), de már M₀-ban Σp∈P M₀(p) = 2 ≠ 1, tehát nem 1-safe. ∎

Minimális ellenpélda (|P| + |T| = 1): P = {p₁}, T = ∅, M₀ = (2). Semmi sem tüzelhet, ezért R(M₀) = {M₀}. Σp∈P M₀(p) = 2: korlátos k = 2-vel, de nem 1-safe.

Miért nem lehet kisebb? Mérete 1, és 0 méretű háló nincs. Ha a definíció T ≠ ∅-t is megköveteli, egy élek nélküli t hozzáadásával (méret 2) ugyanez működik: t mindig tüzelhet, de a jelölést nem változtatja.

2. Összeges és helyenkénti definíció

igaz

Σp∈P M(p) = 1 ⇒ ∀p ∈ P : M(p) ≤ 1

Bizonyítás. Minden tag nemnegatív, ezért bármely p ∈ P-re M(p) ≤ Σq∈P M(q) = 1. Ez minden M ∈ R(M₀)-ra igaz, tehát az összeges 1-safe-ből következik a helyenkénti. ∎

nem igaz

∀p ∈ P : M(p) ≤ 1 ⇒ Σp∈P M(p) = 1

Ellenpélda: két független, egytokenes kör egy hálóban. P = {p₁, p₂, p₃, p₄}, M₀ = (1, 0, 1, 0); t₁ és t₂ p₁ és p₂ között, t₃ és t₄ p₃ és p₄ között viszi körbe a tokent. A két kör nem ér össze, ezért mindkettőben mindig pontosan 1 token van. Így ∀M ∈ R(M₀) ∀p ∈ P : M(p) ≤ 1 (helyenként 1-safe), de Σp∈P M(p) = 2 ≠ 1. ∎

Minimális ellenpélda (|P| + |T| = 1): P = {p₁}, T = ∅, M₀ = (0). R(M₀) = {M₀}, és M₀(p₁) = 0 ≤ 1, tehát helyenként 1-safe, de Σp∈P M₀(p) = 0 ≠ 1.

Miért nem lehet kisebb? Mérete 1, és 0 méretű háló nincs. (T ≠ ∅ megkövetelése esetén itt is elég egy élek nélküli tranzíció.)

ekvivalens

bounded összeggel ⟺ bounded helyenként

Bizonyítás. (⇒) Ha ∀M ∈ R(M₀) : Σp∈P M(p) ≤ k, akkor minden tag is legfeljebb k: M(p) ≤ k. (⇐) Ha ∀M ∈ R(M₀) ∀p ∈ P : M(p) ≤ k, akkor Σp∈P M(p) ≤ k · |P|, és ez véges szám, mert P véges. Tehát k · |P| jó korlát. ∎

3. Live és deadlock-free (feltéve, hogy T ≠ ∅)

igaz

live ⇒ deadlock-free

Bizonyítás. Legyen M ∈ R(M₀) tetszőleges. Be kell látni, hogy ∃t ∈ T : t ∈ E(M). Mivel T ≠ ∅, vehetünk egy t ∈ T-t. Az élőség miatt ∃M′ ∈ R(M) : t ∈ E(M′). Tekintsük az M-ből M′-be vezető véges futást. Ha 0 lépéses, akkor M′ = M, és t ∈ E(M). Ha legalább 1 lépéses, akkor az első tüzelő tranzíciója, t₁, az M-ben tüzelt, tehát t₁ ∈ E(M). Mindkét esetben E(M) ≠ ∅. ∎

A T ≠ ∅ feltétel kell: ha nincs tranzíció, a „live" formula üres ∀t miatt igaz, de E(M₀) = ∅, tehát van holtpont.

nem igaz

deadlock-free ⇒ live

Ellenpélda: a „Nem élő" háló (Live), helyek p₀, p₁, p₂, M₀ = (1, 0, 0). R(M₀) = {(1,0,0), (0,1,0), (0,0,1)}, és ezekben rendre t₀, t₁, t₂ engedélyezett, tehát holtpontmentes. De M = (0,1,0)-ra R(M) = {(0,1,0), (0,0,1)}, és mindkettőben M(p₀) = 0 < 1 = w(p₀,t₀), így t₀ ∉ E(M′) egyetlen M′ ∈ R(M)-re sem. Tehát nem élő. ∎

Minimális ellenpélda (|P| + |T| = 3): P = {p}, T = {t₁, t₂}, F = {(p,t₁), (t₁,p), (p,t₂)}, w(p,t₂) = 2, a többi súly 1, M₀ = (1). t₁ hurok: elvesz és visszatesz egy tokent, ezért R(M₀) = {(1)} és t₁ ∈ E((1)): holtpontmentes. t₂-höz 2 token kellene, de p-n mindig csak 1 van, ezért t₂ halott: nem élő.

Miért nem lehet kisebb? Nézzük végig a 3-nál kisebb hálókat. Ha T = ∅, akkor E(M₀) = ∅, nem holtpontmentes. Ha P = ∅, akkor minden tranzíciónak üres a bemenete, mindig engedélyezett, tehát élő. Marad |P| = |T| = 1: itt a holtpontmentesség miatt az egyetlen t minden elérhető jelölésben engedélyezett, tehát élő. Így legalább 3 elem kell.

4. Terminating és deadlock

igaz

terminating ⇒ van deadlock

Bizonyítás. Maximális sorozat mindig létezik: M₀-ból addig tüzelünk egy-egy engedélyezett tranzíciót, amíg lehet. Legyen ez OS(M₀). A terminálás miatt van b, hogy |OS(M₀)| ≤ b. Tehát ∃b ∈ ℕ ∃OS(M₀) : |OS(M₀)| ≤ b, ami épp a Deadlock definíciója. (Kifejtve: a sorozat véges, és maximális, ezért utolsó jelölésére E(Mn) = ∅, és Mn ∈ R(M₀).) ∎

nem igaz

van deadlock ⇒ terminating

Ellenpélda: a „Fordított sorrend" háló (Deadlock). Holtpont: tA1, majd tB1 tüzelése után A₁-ben és B₁-ben van token, r₁ és r₂ üres, és E(M) = ∅. De végtelen futás is van: tA1, tA2, tA3, tA1, tA2, tA3, … Az A folyamat körbejár, B közben B₀-ban vár. Minden lépés engedélyezett, és minden harmadik lépés után visszaérünk M₀-ba. Tehát a háló nem termináló. ∎

Minimális ellenpélda (|P| + |T| = 3): ugyanaz a háló, mint a 3. pont minimális ellenpéldája, csak w(p,t₂) = 1. M₀ = (1). R(M₀) = {(1), (0)}. t₂ tüzelése után M = (0), és E(M) = ∅: van holtpont. De a t₁, t₁, t₁, … futás végtelen: nem termináló.

Miért nem lehet kisebb? Ha T = ∅, nincs végtelen futás. Ha P = ∅, minden tranzíció mindig engedélyezett, nincs holtpont. Ha |P| = |T| = 1, minden lépésben az egyetlen t az egyetlen választás, így csak egy futás van. Ha ez véges, nincs végtelen futás. Ha végtelen, minden elérhető jelölés rajta van, és mindben t ∈ E(M), tehát nincs holtpont. Így legalább 3 elem kell.

Érdemes összevetni a 3. ponttal: a két minimális háló csak egyetlen élsúlyban tér el, és ettől az egyik holtpontmentes, a másik nem.

5. Live és terminating (feltéve, hogy T ≠ ∅)

igaz

live ⇒ nem terminating

Bizonyítás. Indirekt: tegyük fel, hogy a háló élő és termináló is. A 4. pont szerint terminálóból ∃M ∈ R(M₀) : E(M) = ∅. A 3. pont szerint élőből ∀M ∈ R(M₀) : E(M) ≠ ∅. A kettő ellentmond egymásnak. ∎

nem igaz

nem terminating ⇒ live

Ellenpélda: a 3. pont ábráján látható háló. Van végtelen futása (t₀, t₁, t₂, t₁, t₂, …), tehát nem termináló, de a 3. pont szerint nem élő. ∎

Minimális ellenpélda (|P| + |T| = 3): a 3. pont minimális hálója (w(p,t₂) = 2, M₀ = (1)). A t₁, t₁, … futás végtelen, tehát nem termináló, de t₂ halott, tehát nem élő.

Miért nem lehet kisebb? Ha T = ∅, a háló terminál. Ha P = ∅, minden tranzíció mindig engedélyezett, tehát élő. Ha |P| = |T| = 1, csak egy futás van. Ha ez végtelen, minden elérhető jelölés rajta van, mindben t ∈ E(M), tehát a háló élő. Így legalább 3 elem kell.

6. Reversible és home state

igaz

reversible ⇒ van home state

Bizonyítás. Legyen M′ = M₀. Ekkor M′ ∈ R(M₀) (0 lépés), és a reverzibilitás miatt ∀M ∈ R(M₀) : M₀ ∈ R(M). Tehát ∃M′ ∈ R(M₀) ∀M ∈ R(M₀) : M′ ∈ R(M). ∎

nem igaz

van home state ⇒ reversible

Ellenpélda: a „Nem reverzibilis" háló (Reversible), M₀ = (1, 0, 0). R(M₀) = {(1,0,0), (0,1,0), (0,0,1)}. M′ = (0,1,0) home state: (1,0,0)-ból t₁-gyel, (0,1,0)-ból 0 lépéssel, (0,0,1)-ből t₃-mal elérhető. De M = (0,1,0)-ból M₀ nem érhető el: R(M) = {(0,1,0), (0,0,1)}, mindkettőben M(p₁) = 0, mert nincs olyan t, amelyre (t,p₁) ∈ F. ∎

Minimális ellenpélda (|P| + |T| = 2): P = {p}, T = {t}, F = {(p,t)}, M₀ = (1). t elfogyasztja a tokent: R(M₀) = {(1), (0)}. (0) home state: (1)-ből t-vel, (0)-ból 0 lépéssel elérhető. De (0)-ból (1) nem érhető el, tehát nem reverzibilis.

Miért nem lehet kisebb? 1 elemű háló esetén T = ∅, vagy P = ∅ és egyetlen, élek nélküli t van. Mindkét esetben R(M₀) = {M₀}, ami reverzibilis.

7. Reversible és live

Egy hasznos tény: az elérhetőség tranzitív. Ha M′ ∈ R(M) és M″ ∈ R(M′), akkor M″ ∈ R(M), mert a két futást egymás után fűzve M-ből M″-be jutunk.

igaz, feltétellel

reversible ∧ (∀t ∈ T ∃M ∈ R(M₀) : t ∈ E(M)) ⇒ live

A feltétel: nincs halott tranzíció, vagyis minden t legalább egyszer tüzelhet M₀-ból indulva (L1). Ez ésszerű kikötés: ami M₀-ból semmilyen futásban nem tüzelhet, annak nincs szerepe a hálóban, el is hagyható.

Bizonyítás. Legyen t ∈ T és M ∈ R(M₀) tetszőleges. Keresünk M′ ∈ R(M)-et, amelyre t ∈ E(M′). A feltétel szerint van M* ∈ R(M₀), amelyre t ∈ E(M*). A reverzibilitás szerint M₀ ∈ R(M). A tranzitivitás miatt M₀ ∈ R(M)-ből és M* ∈ R(M₀)-ból M* ∈ R(M). Tehát M′ = M* megfelel. Mivel t és M tetszőleges volt, ∀t ∈ T ∀M ∈ R(M₀) ∃M′ ∈ R(M) : t ∈ E(M′). ∎

Szemléletesen: bárhonnan vissza tudunk menni M₀-ba, és M₀-ból ugyanazt az utat bejárva újra eljutunk oda, ahol t tüzelhet.

feltétel nélkül nem

reversible ⇒ live

Ellenpélda (ezért kell a feltétel): az 1 tokenes kör (p₁, p₂, p₃, t₁, t₂, t₃), kiegészítve egy p₄ hellyel és egy t₄ tranzícióval: (p₄,t₄) ∈ F, (t₄,p₁) ∈ F, M₀ = (1, 0, 0, 0). p₄-be nem vezet nyíl, ezért M(p₄) = 0 minden elérhető M-ben, így t₄ ∉ E(M) sosem. A kör három lépésenként visszaér M₀-ba, minden elérhető jelölésből: reverzibilis. De t₄ halott, tehát nem élő. Pont ez a t₄ az, amit a feltétel kizár. ∎

Minimális ellenpélda (|P| + |T| = 2): P = {p}, T = {t}, F = {(p,t)}, M₀ = (0). R(M₀) = {(0)}, ez triviálisan reverzibilis. t-hez 1 token kellene, de p mindig üres: t halott, nem élő. (Ez a háló a feltételt is sérti, ahogy kell.)

Miért nem lehet kisebb? 1 elemű háló esetén T = ∅, és akkor a live formula üres ∀t miatt igaz, vagy P = ∅, és az egyetlen t mindig engedélyezett, tehát élő.

nem igaz

live ⇒ reversible

Ellenpélda: P = {p₁, p₂, p₃}, M₀ = (1, 0, 0). t₁: (p₁,t₁), (t₁,p₁), (t₁,p₂) ∈ F, t₂: (p₂,t₂), (t₂,p₃) ∈ F, minden súly 1. M(p₁) = 1 mindig, ezért t₁ ∈ E(M) minden elérhető M-ben. Bármely M-ből t₁ tüzelése után M′(p₂) ≥ 1, tehát t₂ ∈ E(M′). Így a háló élő (és nincs halott tranzíciója). De p₃-ból nem indul nyíl, ezért M(p₃) sosem csökken. t₁, t₂ után M(p₃) = 1, és innen M₀ (ahol M₀(p₃) = 0) többé nem érhető el. Tehát nem reverzibilis. ∎

Minimális ellenpélda (|P| + |T| = 2): P = {p}, T = {t}, F = {(t,p)}, M₀ = (0). t-nek nincs bemeneti helye, ezért mindig engedélyezett: élő. Minden tüzelés eggyel növeli M(p)-t, ezért (1)-ből (0) = M₀ már nem érhető el: nem reverzibilis.

Miért nem lehet kisebb? 1 elemű hálóban R(M₀) = {M₀} (vagy nincs tranzíció, vagy az egyetlen tranzíciónak nincs éle), ez pedig reverzibilis.

Kiterjesztés · Inhibitor arcs

Tiltó élek

A tiltó él (inhibitor arc) egy helyről egy tranzícióba mutat, és a végén nyílhegy helyett kis karika van. Jelentése fordított: a tranzíció csak akkor tüzelhet, ha azon a helyen nincs token. A tiltó él tokent nem mozgat, csak „figyel". Ezzel a háló nullára tud tesztelni: „csak akkor, ha üres a puffer".

A háló kiegészítve a tiltó élek halmazávalN = (P, T, F, I, w, M₀),   I ⊆ P × T

(p,t) ∈ I: tiltó él megy p-ből t-be. Közönséges él és tiltó él ugyanazon (p, t) pár között nem szokás egyszerre.

Engedélyezettség tiltó élekkelt ∈ E(M)  ⟺  ∀p ∈ P :  ((p,t) ∈ F ⇒ M(p) ≥ w(p,t))  ∧  ((p,t) ∈ I ⇒ M(p) = 0)
  1. t ∈ E(M) ⟺ ∀p ∈ P :„t pontosan akkor engedélyezett M-ben, ha minden p helyre igaz, hogy…
  2. (p,t) ∈ F ⇒ M(p) ≥ w(p,t)…ha p-ből közönséges nyíl megy t-be, ott van elég token (ez a régi feltétel),…
  3. (p,t) ∈ I ⇒ M(p) = 0…és ha p-ből tiltó él megy t-be, akkor p üres."

A tüzelés képlete változatlan: ∀p ∈ P : M′(p) = M(p) − w(p,t) + w(t,p), mert w csak az F-beli éleken nem nulla. A tiltó élen nem mozog token. (Általánosabb változatban a tiltó élnek is van súlya, és a feltétel M(p) < w(p,t). A súly nélküli, nullára tesztelő alak ennek w = 1 esete.)

Mi marad változatlan? Mind a hat tulajdonság formulája szó szerint ugyanaz, mert mindegyik csak E(M)-en, R(M₀)-on és OS(M)-en keresztül hivatkozik a hálóra. R és OS is E-ből épül fel, és ezek közül csak E definíciója bővült. A bizonyítások is érvényesek maradnak: csak E-t, R-t és az elérhetőség tranzitivitását használják.

0 · Definition and firing rule

Basics: the net, and when does a transition fire?

Petri netN = (P, T, F, w, M₀),   F ⊆ (P×T) ∪ (T×P),   w : F → ℕ⁺,   M₀ : P → ℕ

The initial marking is part of the net. The same drawing started from a different M₀ gives a completely different state space. The two nets of the 1-safe chapter have the same (P, T, F, w) structure: with 1 token it is 1-safe, with 2 tokens it is not. If the same ring is started from M₀ = (0, 0, 0), it is deadlocked immediately. That is why the six properties on this page are behavioral properties: they always refer to the complete net (P, T, F, w, M₀).

Structural properties. If we drop M₀, we can still state things about the structure (P, T, F, w) by quantifying over M₀. For example, structurally bounded: for ∀M₀ : P → ℕ, (P, T, F, w, M₀) is bounded. Structurally live: ∃M₀ : P → ℕ such that (P, T, F, w, M₀) is live. The quantifier matters here too: bounded must hold for every initial marking, live needs only one.

Firing rule

Every property builds on this. A transition is enabled if every place that has an arrow into it holds at least as many tokens as the weight of that arrow. When it fires, it takes these tokens and puts new ones along its outgoing arrows.

Enablingt ∈ E(M)  ⟺  ∀p ∈ P :  (p,t) ∈ F ⇒ M(p) ≥ w(p,t)
  1. t ∈ E(M) ⟺“t is an element of the set of transitions enabled in M if and only if…
  2. ∀p ∈ P : (p,t) ∈ F ⇒…for every place p with an arrow into t it holds that…
  3. M(p) ≥ w(p,t)…that place has at least as many tokens as the arrow takes.”
Firing: if t ∈ E(M), the new marking is M′∀p ∈ P :  M′(p) = M(p) − w(p,t) + w(t,p)

Where there is no arrow, w = 0, so the token count of that place does not change.

Reachable markings, built step by step(1)  M₀ ∈ R(M₀)
(2)  ∀M ∈ R(M₀)  ∀t ∈ E(M) :  M′ ∈ R(M₀),  where M′ is the result of firing t
  1. M₀ ∈ R(M₀)“The initial marking is reachable (in 0 steps).
  2. ∀M ∈ R(M₀) ∀t ∈ E(M)If a marking is reachable and t is enabled in it,…
  3. M′ ∈ R(M₀)…then the marking after the firing is also reachable.” There are no other reachable markings.

Occurrence sequence: OS(M)

Maximal occurrence sequence from MOS(M) = M  t₁  M₁  t₂  M₂  …,   where ∀i : ti+1 ∈ E(Mi) and Mi+1 is the result of firing ti+1

The sequence is maximal: either it is infinite, or it ends in a marking Mn where E(Mn) = ∅, so it cannot be continued. Usually many such sequences start from an M (they branch at every choice). ∀OS(M) means “for any such sequence”, ∃OS(M) means “there is such a sequence”.

  1. |OS(M)|the length of the sequence: how many transitions fire in it. For an infinite sequence it is ∞, which is not ≤ any b ∈ ℕ.
  2. M′ ∈ OS(M)M′ occurs among the markings of the sequence.
  3. t ∈ OS(M)t fires somewhere in the sequence.

Why maximality? If any (extendable) sequence were allowed, the empty sequence would also be an OS(M₀), of length 0. Then the Deadlock formula (below) would hold for every net, and the Deadlock-free formula would be false for every net. Maximality does not affect the Terminating, Reversible and Live formulas, because a finite sequence can always be extended to a maximal one.

1 · 1-safe

Safe (1-safe)

However long we run the net, it always holds exactly one token in total. The net then behaves like a state machine: the position of the token shows which state the system is in.

Used on this page∀M ∈ R(M₀) :  Σp∈P M(p) = 1
  1. ∀M ∈ R(M₀)“Take any marking reachable from the initial marking…
  2. Σp∈P M(p)…and add up the token counts of all places…
  3. = 1…the sum is exactly 1.”
Per-place definition, common in the literature∀M ∈ R(M₀)  ∀p ∈ P :  M(p) ≤ 1

The two are not the same. The per-place variant only asks that no place holds more than 1 token. This follows from the sum variant: if the sum is 1, no term can exceed 1. The converse fails: two tokens on two different places, or no token at all, is ≤ 1 per place, but the sum is not 1. So the sum definition is stronger. See the proofs.

2 · Bounded

Bounded

There is a fixed number k such that the net never holds more than k tokens in total. In practice: buffers have finite size, the system does not “overflow”.

Used on this page∃k ∈ ℕ  ∀M ∈ R(M₀) :  Σp∈P M(p) ≤ k
  1. ∃k ∈ ℕ“There is a natural number k such that…
  2. ∀M ∈ R(M₀)…whichever reachable marking we look at…
  3. Σp∈P M(p) ≤ k…it holds at most k tokens in total.”
Per-place definition, common in the literature∃k ∈ ℕ  ∀M ∈ R(M₀)  ∀p ∈ P :  M(p) ≤ k

Here the two are equivalent, because P is finite. If the sum is at most k, every term is at most k. If every place holds at most k tokens, the sum is at most k·|P| (|P| is the number of places). The value of the bound may differ, but a bound exists in one sense exactly when it exists in the other.

The order is what matters. k must be chosen in advance, as one common bound, and then work for every marking. Written the other way round, ∀M ∈ R(M₀) ∃k ∈ ℕ : Σp∈P M(p) ≤ k would always be true: every single marking holds finitely many tokens, so each one has its own k. That is exactly what happens in the unbounded variant: at every step there is a bound, but it keeps growing.

theorem

bounded ⟺ R(M₀) is finite (finite state space)

Proof. (⇒) Let m = |P|. If every reachable marking has Σp∈P M(p) ≤ b, then the elements of R(M₀) are among the markings that distribute at most b tokens over m places. Exactly j tokens can be distributed in C(j+m−1, m−1) ways (stars and bars: the order of j stars and m−1 bars). At most b tokens in C(b+m, m) ways (with one extra “leftover” place). This is a finite number, so R(M₀) is finite. (⇐) If R(M₀) is finite, let b = maxM∈R(M₀) Σp∈P M(p). This is a valid bound. ∎

Example: m = 4 places, b = 6 tokens; with exactly 6 tokens there are C(9, 3) = 84 possible markings.

3 · Terminating

Terminating

Whichever transitions we choose to fire, the net stops after finitely many steps. There is no infinite run.

Definition∃b ∈ ℕ  ∀OS(M₀) :  |OS(M₀)| ≤ b
  1. ∃b ∈ ℕ“There is a number b such that…
  2. ∀OS(M₀)…whichever maximal occurrence sequence starting from M₀ we look at,…
  3. |OS(M₀)| ≤ b…it is at most b steps long.”

An infinite sequence has length ∞, which is not ≤ any b, so the formula also rules out infinite runs.

Written out with E: no infinite run¬ ∃t₁, t₂, … ∈ T  ∃M₁, M₂, …  ∀i ∈ ℕ :
 ti+1 ∈ E(Mi)  ∧  ∀p ∈ P : Mi+1(p) = Mi(p) − w(p,ti+1) + w(ti+1,p)
  1. ¬ ∃t₁, t₂, … ∈ T“There is no infinite sequence of transitions…
  2. ∃M₁, M₂, ……with a matching infinite sequence of markings (starting from M₀)…
  3. ∀i ∈ ℕ…such that for every i-th step:
  4. ti+1 ∈ E(Mi)the next transition is enabled in the current marking,…
  5. ∀p ∈ P : Mi+1(p) = ……and the next marking is exactly the result of the firing.”

Why are the two the same? The definition says that run lengths are bounded; the written-out form says that there is no infinite run. Arrange the runs in a tree: the root is M₀, and the children of a marking are the markings reachable from it by one firing. Since T is finite, every node has finitely many children. By Kőnig’s lemma, if there is no infinite branch, the tree is finite, so branch lengths are bounded.

4 · Deadlock

Deadlock and deadlock-freedom

A deadlock is a reachable marking in which no transition at all is enabled: the system is stuck. The classic example: two processes take two resources in opposite order, and each waits for the resource held by the other.

M is a dead marking∀t ∈ T :  t ∉ E(M)  (in short: E(M) = ∅)
The net has a deadlock∃b ∈ ℕ  ∃OS(M₀) :  |OS(M₀)| ≤ b
  1. ∃b ∈ ℕ“There is a number b…
  2. ∃OS(M₀)…and there is a maximal occurrence sequence starting from M₀…
  3. |OS(M₀)| ≤ b…that is at most b long”, i.e. finite.

A finite maximal sequence ends because its last marking has E(M) = ∅. That marking is the deadlock. Here b could be dropped (it is enough that a finite maximal sequence exists), but with it the parallel is clear: Terminating is ∃b ∀OS, Deadlock is ∃b ∃OS.

Written out with E∃M ∈ R(M₀)  ∀t ∈ T :  t ∉ E(M)
Deadlock-free: the negation of the above∀b ∈ ℕ  ∀OS(M₀) :  |OS(M₀)| > b
  1. ∀b ∈ ℕ“However large a number b we choose,…
  2. ∀OS(M₀)…every maximal occurrence sequence starting from M₀…
  3. |OS(M₀)| > b…is longer than b”, i.e. every maximal run is infinite.
Written out with E∀M ∈ R(M₀)  ∃t ∈ T :  t ∈ E(M)

Steps of the negation: ¬∃b ∃OS : |OS| ≤ b  →  ∀b ¬∃OS : |OS| ≤ b  →  ∀b ∀OS : ¬(|OS| ≤ b)  →  ∀b ∀OS : |OS| > b. At every step the ¬ moves one quantifier inward, and that quantifier flips.

5 · Reversible

Reversible

Whatever state the net has reached, there is always a way back to the initial marking. In practice: the system can always return to its “reset” state, e.g. a protocol gets back to its idle state after every exchange.

∀M ∈ R(M₀)  ∃OS(M) :  M₀ ∈ OS(M)
  1. ∀M ∈ R(M₀)“For every reachable marking it holds that…
  2. ∃OS(M)…there is a maximal occurrence sequence starting from it…
  3. M₀ ∈ OS(M)…in which the initial marking occurs again.”
Written out∀M ∈ R(M₀) :  M₀ ∈ R(M)
Generalization: a home state exists∃M′ ∈ R(M₀)  ∀M ∈ R(M₀) :  M′ ∈ R(M)

This is weaker: there is some reachable “home” marking that can always be returned to, but it is not necessarily the initial marking.

6 · Live

Live (L4-live)

Whichever transition we look at, and whatever state the net has reached, there is always a continuation in which that transition can fire again. No transition “dies” for good. This is stronger than deadlock-freedom, which only asks that something can always fire.

∀M ∈ R(M₀)  ∀t ∈ T  ∃OS(M) :  t ∈ OS(M)
  1. ∀M ∈ R(M₀)“For every reachable marking…
  2. ∀t ∈ T…and every transition…
  3. ∃OS(M)…there is a maximal occurrence sequence starting from M…
  4. t ∈ OS(M)…in which t fires.”

The two ∀ can be swapped, because they are quantifiers of the same kind.

Written out with E∀t ∈ T  ∀M ∈ R(M₀)  ∃M′ ∈ R(M) :  t ∈ E(M′)
LevelFormula for a given tIn words
L0 (dead)∀M ∈ R(M₀) : t ∉ E(M)t can never fire, in no reachable marking.
L1∃M ∈ R(M₀) : t ∈ E(M)t can fire at least once (the negation of L0).
L4 (live)∀M ∈ R(M₀) ∃M′ ∈ R(M) : t ∈ E(M′)can be made to fire again from anywhere.

Proofs: implications and counterexamples

To prove A ⇒ B, we show that every net in which A holds also satisfies B. To show that the implication does not hold, one net (a counterexample) in which A holds and B does not is enough. The net of every counterexample runs right here. Places are listed in the marking vector in the order p₁, p₂, …

Next to every counterexample we also give the minimal one: the one in which the total number of places and transitions, |P| + |T|, is as small as possible. We assume P ∪ T ≠ ∅, otherwise there is no net. In the figures the “Minimal” button switches to it.

1. 1-safe and bounded

true

1-safe ⇒ bounded

Proof. Assume ∀M ∈ R(M₀) : Σp∈P M(p) = 1. Choose k = 1. Then for every M ∈ R(M₀), Σp∈P M(p) = 1 ≤ k. Hence ∃k ∈ ℕ ∀M ∈ R(M₀) : Σp∈P M(p) ≤ k. ∎

false

bounded ⇒ 1-safe

Counterexample: the 2-token ring (Bounded, “Bounded”), M₀ = (1, 0, 1). Every transition has one input and one output place, both arcs of weight 1. So every firing takes 1 token and puts 1 back, hence ∀M ∈ R(M₀) : Σp∈P M(p) = 2. The net is bounded (k = 2), but already in M₀, Σp∈P M₀(p) = 2 ≠ 1, so it is not 1-safe. ∎

Minimal counterexample (|P| + |T| = 1): P = {p₁}, T = ∅, M₀ = (2). Nothing can fire, so R(M₀) = {M₀}. Σp∈P M₀(p) = 2: bounded with k = 2, but not 1-safe.

Why can’t it be smaller? Its size is 1, and there is no net of size 0. If the definition also requires T ≠ ∅, adding a t without arcs (size 2) works the same way: t can always fire, but it does not change the marking.

2. Sum and per-place definitions

true

Σp∈P M(p) = 1 ⇒ ∀p ∈ P : M(p) ≤ 1

Proof. Every term is non-negative, so for any p ∈ P, M(p) ≤ Σq∈P M(q) = 1. This holds for every M ∈ R(M₀), so the per-place 1-safe property follows from the sum one. ∎

false

∀p ∈ P : M(p) ≤ 1 ⇒ Σp∈P M(p) = 1

Counterexample: two independent one-token loops in one net. P = {p₁, p₂, p₃, p₄}, M₀ = (1, 0, 1, 0); t₁ and t₂ move the token between p₁ and p₂, t₃ and t₄ between p₃ and p₄. The two loops do not touch, so each always holds exactly 1 token. Hence ∀M ∈ R(M₀) ∀p ∈ P : M(p) ≤ 1 (1-safe per place), but Σp∈P M(p) = 2 ≠ 1. ∎

Minimal counterexample (|P| + |T| = 1): P = {p₁}, T = ∅, M₀ = (0). R(M₀) = {M₀} and M₀(p₁) = 0 ≤ 1, so it is 1-safe per place, but Σp∈P M₀(p) = 0 ≠ 1.

Why can’t it be smaller? Its size is 1, and there is no net of size 0. (If T ≠ ∅ is required, a transition without arcs is enough here too.)

equivalent

bounded by sum ⟺ bounded per place

Proof. (⇒) If ∀M ∈ R(M₀) : Σp∈P M(p) ≤ k, then every term is at most k as well: M(p) ≤ k. (⇐) If ∀M ∈ R(M₀) ∀p ∈ P : M(p) ≤ k, then Σp∈P M(p) ≤ k · |P|, which is a finite number because P is finite. So k · |P| is a valid bound. ∎

3. Live and deadlock-free (assuming T ≠ ∅)

true

live ⇒ deadlock-free

Proof. Let M ∈ R(M₀) be arbitrary. We must show ∃t ∈ T : t ∈ E(M). Since T ≠ ∅, we can take some t ∈ T. By liveness, ∃M′ ∈ R(M) : t ∈ E(M′). Consider the finite run from M to M′. If it has 0 steps, then M′ = M and t ∈ E(M). If it has at least 1 step, its first transition, t₁, fired in M, so t₁ ∈ E(M). In both cases E(M) ≠ ∅. ∎

The condition T ≠ ∅ is needed: with no transitions, the “live” formula is true because of the empty ∀t, but E(M₀) = ∅, so there is a deadlock.

false

deadlock-free ⇒ live

Counterexample: the “Not live” net (Live), places p₀, p₁, p₂, M₀ = (1, 0, 0). R(M₀) = {(1,0,0), (0,1,0), (0,0,1)}, and in these t₀, t₁, t₂ are enabled respectively, so it is deadlock-free. But for M = (0,1,0), R(M) = {(0,1,0), (0,0,1)}, and in both M(p₀) = 0 < 1 = w(p₀,t₀), so t₀ ∉ E(M′) for every M′ ∈ R(M). Hence it is not live. ∎

Minimal counterexample (|P| + |T| = 3): P = {p}, T = {t₁, t₂}, F = {(p,t₁), (t₁,p), (p,t₂)}, w(p,t₂) = 2, all other weights 1, M₀ = (1). t₁ is a self-loop: it takes a token and puts it back, so R(M₀) = {(1)} and t₁ ∈ E((1)): deadlock-free. t₂ would need 2 tokens, but p always holds only 1, so t₂ is dead: not live.

Why can’t it be smaller? Let us check the nets smaller than 3. If T = ∅, then E(M₀) = ∅: not deadlock-free. If P = ∅, every transition has an empty input, is always enabled, so the net is live. That leaves |P| = |T| = 1: here deadlock-freedom means the only t is enabled in every reachable marking, so the net is live. So at least 3 elements are needed.

4. Terminating and deadlock

true

terminating ⇒ has deadlock

Proof. A maximal sequence always exists: starting from M₀, keep firing some enabled transition as long as possible. Call it OS(M₀). By termination there is a b with |OS(M₀)| ≤ b. Hence ∃b ∈ ℕ ∃OS(M₀) : |OS(M₀)| ≤ b, which is exactly the definition of Deadlock. (Written out: the sequence is finite and maximal, so its last marking has E(Mn) = ∅, and Mn ∈ R(M₀).) ∎

false

has deadlock ⇒ terminating

Counterexample: the “Opposite order” net (Deadlock). Deadlock: after tA1 and then tB1 fire, A₁ and B₁ hold a token, r₁ and r₂ are empty, and E(M) = ∅. But there is also an infinite run: tA1, tA2, tA3, tA1, tA2, tA3, … Process A goes round while B waits in B₀. Every step is enabled, and every third step we are back in M₀. So the net is not terminating. ∎

Minimal counterexample (|P| + |T| = 3): the same net as the minimal counterexample of item 3, but with w(p,t₂) = 1. M₀ = (1). R(M₀) = {(1), (0)}. After t₂ fires, M = (0) and E(M) = ∅: there is a deadlock. But the run t₁, t₁, t₁, … is infinite: not terminating.

Why can’t it be smaller? If T = ∅, there is no infinite run. If P = ∅, every transition is always enabled, so there is no deadlock. If |P| = |T| = 1, the only t is the only choice at every step, so there is only one run. If it is finite, there is no infinite run. If it is infinite, every reachable marking lies on it and t ∈ E(M) in all of them, so there is no deadlock. So at least 3 elements are needed.

Compare with item 3: the two minimal nets differ in a single arc weight, and that alone makes one deadlock-free and the other not.

5. Live and terminating (assuming T ≠ ∅)

true

live ⇒ not terminating

Proof. By contradiction: assume the net is both live and terminating. By item 4, terminating gives ∃M ∈ R(M₀) : E(M) = ∅. By item 3, live gives ∀M ∈ R(M₀) : E(M) ≠ ∅. The two contradict each other. ∎

false

not terminating ⇒ live

Counterexample: the net in the figure of item 3. It has an infinite run (t₀, t₁, t₂, t₁, t₂, …), so it is not terminating, but by item 3 it is not live. ∎

Minimal counterexample (|P| + |T| = 3): the minimal net of item 3 (w(p,t₂) = 2, M₀ = (1)). The run t₁, t₁, … is infinite, so it is not terminating, but t₂ is dead, so it is not live.

Why can’t it be smaller? If T = ∅, the net terminates. If P = ∅, every transition is always enabled, so it is live. If |P| = |T| = 1, there is only one run. If it is infinite, every reachable marking lies on it and t ∈ E(M) in all of them, so the net is live. So at least 3 elements are needed.

6. Reversible and home state

true

reversible ⇒ has home state

Proof. Let M′ = M₀. Then M′ ∈ R(M₀) (0 steps), and by reversibility ∀M ∈ R(M₀) : M₀ ∈ R(M). Hence ∃M′ ∈ R(M₀) ∀M ∈ R(M₀) : M′ ∈ R(M). ∎

false

has home state ⇒ reversible

Counterexample: the “Not reversible” net (Reversible), M₀ = (1, 0, 0). R(M₀) = {(1,0,0), (0,1,0), (0,0,1)}. M′ = (0,1,0) is a home state: reachable from (1,0,0) via t₁, from (0,1,0) in 0 steps, from (0,0,1) via t₃. But M₀ is not reachable from M = (0,1,0): R(M) = {(0,1,0), (0,0,1)}, and both have M(p₁) = 0, because there is no t with (t,p₁) ∈ F. ∎

Minimal counterexample (|P| + |T| = 2): P = {p}, T = {t}, F = {(p,t)}, M₀ = (1). t consumes the token: R(M₀) = {(1), (0)}. (0) is a home state: reachable from (1) via t and from (0) in 0 steps. But (1) is not reachable from (0), so the net is not reversible.

Why can’t it be smaller? In a net of size 1 either T = ∅, or P = ∅ and there is a single t without arcs. In both cases R(M₀) = {M₀}, which is reversible.

7. Reversible and live

A useful fact: reachability is transitive. If M′ ∈ R(M) and M″ ∈ R(M′), then M″ ∈ R(M), because concatenating the two runs leads from M to M″.

true, with a condition

reversible ∧ (∀t ∈ T ∃M ∈ R(M₀) : t ∈ E(M)) ⇒ live

The condition: there is no dead transition, i.e. every t can fire at least once starting from M₀ (L1). This is a reasonable requirement: a transition that cannot fire in any run from M₀ plays no role in the net and can be dropped.

Proof. Let t ∈ T and M ∈ R(M₀) be arbitrary. We look for M′ ∈ R(M) with t ∈ E(M′). By the condition there is M* ∈ R(M₀) with t ∈ E(M*). By reversibility M₀ ∈ R(M). By transitivity, M₀ ∈ R(M) and M* ∈ R(M₀) give M* ∈ R(M). So M′ = M* works. Since t and M were arbitrary, ∀t ∈ T ∀M ∈ R(M₀) ∃M′ ∈ R(M) : t ∈ E(M′). ∎

Intuitively: from anywhere we can go back to M₀, and from M₀, following the same path again, we get to where t can fire.

false without the condition

reversible ⇒ live

Counterexample (this is why the condition is needed): the 1-token ring (p₁, p₂, p₃, t₁, t₂, t₃), extended with a place p₄ and a transition t₄: (p₄,t₄) ∈ F, (t₄,p₁) ∈ F, M₀ = (1, 0, 0, 0). No arrow leads into p₄, so M(p₄) = 0 in every reachable M, hence never t₄ ∈ E(M). The ring returns to M₀ every three steps, from every reachable marking: reversible. But t₄ is dead, so the net is not live. This t₄ is exactly what the condition excludes. ∎

Minimal counterexample (|P| + |T| = 2): P = {p}, T = {t}, F = {(p,t)}, M₀ = (0). R(M₀) = {(0)}, which is trivially reversible. t would need 1 token, but p is always empty: t is dead, not live. (This net also violates the condition, as it should.)

Why can’t it be smaller? In a net of size 1 either T = ∅, and then the live formula is true because of the empty ∀t, or P = ∅, and the only t is always enabled, so the net is live.

false

live ⇒ reversible

Counterexample: P = {p₁, p₂, p₃}, M₀ = (1, 0, 0). t₁: (p₁,t₁), (t₁,p₁), (t₁,p₂) ∈ F, t₂: (p₂,t₂), (t₂,p₃) ∈ F, all weights 1. M(p₁) = 1 always, so t₁ ∈ E(M) in every reachable M. From any M, after t₁ fires, M′(p₂) ≥ 1, so t₂ ∈ E(M′). So the net is live (and has no dead transition). But no arrow leaves p₃, so M(p₃) never decreases. After t₁, t₂ we have M(p₃) = 1, and from there M₀ (where M₀(p₃) = 0) can never be reached again. So the net is not reversible. ∎

Minimal counterexample (|P| + |T| = 2): P = {p}, T = {t}, F = {(t,p)}, M₀ = (0). t has no input place, so it is always enabled: live. Every firing increases M(p) by one, so from (1) the marking (0) = M₀ can no longer be reached: not reversible.

Why can’t it be smaller? In a net of size 1, R(M₀) = {M₀} (either there is no transition, or the only transition has no arcs), and that is reversible.

Extension · Inhibitor arcs

Inhibitor arcs

An inhibitor arc points from a place to a transition and ends in a small circle instead of an arrowhead. Its meaning is reversed: the transition can fire only if that place holds no token. The inhibitor arc moves no tokens; it only “watches”. With it a net can test for zero: “only if the buffer is empty”.

The net extended with the set of inhibitor arcsN = (P, T, F, I, w, M₀),   I ⊆ P × T

(p,t) ∈ I: an inhibitor arc goes from p to t. An ordinary arc and an inhibitor arc between the same (p, t) pair are usually not allowed together.

Enabling with inhibitor arcst ∈ E(M)  ⟺  ∀p ∈ P :  ((p,t) ∈ F ⇒ M(p) ≥ w(p,t))  ∧  ((p,t) ∈ I ⇒ M(p) = 0)
  1. t ∈ E(M) ⟺ ∀p ∈ P :“t is enabled in M if and only if for every place p it holds that…
  2. (p,t) ∈ F ⇒ M(p) ≥ w(p,t)…if an ordinary arrow goes from p to t, p has enough tokens (the old condition),…
  3. (p,t) ∈ I ⇒ M(p) = 0…and if an inhibitor arc goes from p to t, then p is empty.”

The firing formula is unchanged: ∀p ∈ P : M′(p) = M(p) − w(p,t) + w(t,p), because w is non-zero only on arcs in F. No token moves along an inhibitor arc. (In a more general variant the inhibitor arc also has a weight, and the condition is M(p) < w(p,t). The unweighted, zero-testing form is the case w = 1.)

What stays the same? The formulas of all six properties stay word for word the same, because each refers to the net only through E(M), R(M₀) and OS(M). R and OS are also built from E, and of these only the definition of E has been extended. The proofs remain valid too: they use only E, R and the transitivity of reachability.

What changes?

lost

monotonicity

In an ordinary net: if t ∈ E(M) and ∀p ∈ P : M′(p) ≥ M(p), then t ∈ E(M′). More tokens never disable anything. Proof: if (p,t) ∈ F, then M′(p) ≥ M(p) ≥ w(p,t). ∎

With an inhibitor arc this fails. Counterexample: one place p, one transition t, (p,t) ∈ I. In M = (0), t ∈ E(M), but in M′ = (1), where M′(p) ≥ M(p), t ∉ E(M′). ∎ This is also a minimal counterexample (|P| + |T| = 2), because an arc, and so an inhibitor arc too, can only connect a place and a transition.

lost

decidability

For ordinary nets boundedness and reachability are decidable. Boundedness, for example, is decided by the Karp–Miller tree (coverability tree), which relies on monotonicity. With inhibitor arcs a net can simulate a counter machine: one place for each counter, and a zero test is an inhibitor arc. A two-counter machine is already Turing-complete, so with two inhibitor arcs reachability and boundedness are undecidable in general. The formulas stay the same, but checking them automatically is no longer guaranteed.

Protocol example: retransmit only after a lost message

A stop-and-wait sender over a lossy channel. The sender sends a message and waits for an acknowledgment. The channel either delivers the message (then the receiver sends back an acknowledgment), or the message is lost. The timeout resets the sender so it can retransmit, but only if both the channel and the acknowledgment place are empty. These are the two inhibitor arcs (circle ends). This cannot be expressed with ordinary arcs, because there the condition is “there is a token”; “there is no token” is impossible.

The nets choose at random among the enabled transitions, so every run is different. With the “Step” button you can follow them one step at a time.
